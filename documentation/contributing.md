# 🤝 Contributing to SopuCoder

Thank you for your interest in contributing to SopuCoder! We welcome contributions across datasets, model prompts, benchmarks, and tooling.

## 📋 Ways to Contribute

1. **Dataset Contributions (`datasets/`):**
   - Submit clean, well-tested code samples and instruction pairs.
   - Ensure explicit open-source licensing (permissive licenses only) and proper attribution.
   - Run deduplication and validation checks before submission.

2. **Model Tuning & Modelfiles (`sopu-coder/`, `sopu-coder-fast/`):**
   - Suggest improvements to system prompts, context parameters, or sampling settings.
   - Provide comparative benchmark evaluations against base models.

3. **Benchmarking & Evaluation (`training/evaluation/`):**
   - Add new test scenarios covering modern frameworks (Next.js, FastAPI, Laravel, etc.).
   - Benchmark throughput and latency on varied hardware setups.

4. **Documentation & Guides (`documentation/`):**
   - Improve developer setup guides, Ollama integration tips, and IDE configurations.

## 🚀 Pull Request Workflow

1. Fork the repository and create a feature branch (`git checkout -b feature/your-feature-name`).
2. Make clean, atomic commits adhering to conventional commit guidelines (`feat:`, `fix:`, `docs:`, `chore:`).
3. Test any prompt or benchmark changes locally.
4. Open a Pull Request with a clear description of changes and motivation.
